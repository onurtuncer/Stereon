# Curved analytic surface–surface intersection

Pairs of analytic surfaces with a cone, a torus or an ellipsoid in them, generated by `tools/generate_surface_corpus.py`. Lint checks with `--check` that the files match the generator. With [`analytic-ssi/`](../analytic-ssi/), which holds the plane, sphere and cylinder pairs, it makes up the analytic part of the ADR-0010 corpus. B-spline surfaces are not here: they wait for the generic path.

Each family is one of the fifteen unordered pairs. Each case name is a configuration, a placement and a scale:

| Part | Values |
| --- | --- |
| Configuration | Named for what happens, e.g. `two-ovals`, `coaxial-touching`, `node` |
| Placement | `origin`; `tilted`, a rational rotation and a translation; `far`, translated to (480, −300, 210) m near the edge of the size box |
| Scale | `x1`, or `x100` with every length multiplied by 100 |

## Ground truth

The answer never comes from the kernel. Each configuration's topology follows from a closed-form argument in the generator: the crossings of two coaxial profiles, the known type of a plane section, or a bound on where one surface can meet the other. A tangency that a rotation would turn into a rounding decision of an exact predicate is generated only at the placements where it stays exact.

## Inputs

`inputs.surfaces` is two named surfaces, in millimetres, each with an `x_axis` and a `y_axis`, right-handed:

| `type` | Fields |
| --- | --- |
| `plane` | `origin` |
| `sphere` | `center`, `radius` |
| `cylinder` | `origin`, `radius`, `box` |
| `cone` | `origin`, `radius`, `semi_angle`, `box` |
| `torus` | `center`, `major`, `minor` |
| `ellipsoid` | `center`, `a`, `b`, `c` |

`box` is the parameter domain `[[u0, u1], [v0, v1]]`; a surface without one is intersected over its whole chart. `inputs.tolerance` is the pair's tolerance and `inputs.scale` the case's scale.

## Expected results

| Field | Meaning |
| --- | --- |
| `overlap` | The surfaces coincide over the domains |
| `curves` | The connected curves of the result, branches cut at a seam joined |
| `points` | The isolated points |
| `contact` | `crossing` or `tangential`, for every branch |
| `witnesses` | Points known to lie on the intersection, at least one on each component the argument can place |
| `may_fail_closed` | Present when the case may be refused with `IntersectionFailed`, `CertificationFailed`, `NotSupported` or `NotImplemented`, with the reason. It never excuses a wrong answer |

## What the kernel is held to

`tests/intersect/SurfaceCorpusTests.cpp` holds a result to the expected `curves`, `points` and `contact`; every branch must be certified and stay on both surfaces; every witness must lie on the result. An ordinary test runs the `-tilted-x1` placement of each configuration, in one operand order. The whole suite, in both orders, is the hidden `[exhaustive]` test, which takes minutes in a debug build and runs in the weekly robustness workflow.
