# v0.2 “Intersections” acceptance ledger

Status: open, updated 2026-11-22 to main at #322 (898ed69), which includes
every pull request merged since #305 (#290–#296, #302, #306–#308 and
#310–#323). Implementation entries are not release qualification claims.

Scope (owner's decision of 2026-11-08): the remaining v0.2 work is, in order,
3D curve–curve with reusable Bézier subdivision (merged: #237, #239, #241, #242),
curve–NURBS surface (merged, #249 and since), NURBS–NURBS SSI (in progress: the
Generic SSI row), then corner cases and qualification. Broad curved Booleans
are off the v0.2 critical path: the curved-Boolean items in the *Intersection
to Boolean* and *Native ellipsoid* rows stay listed as later work and do not
block v0.2.

Release gates still open at #322 (details in the rows below):

- *Release qualification*: the supported domain is drafted for the owner's
  decision ([v0.2-supported-domain.md](v0.2-supported-domain.md)), not
  approved. The NURBS SSI reference gate last passed in CI on #317's branch
  (run 44886018197); it has not run in CI on main since #318 and #323
  changed the patch clipping and the certificate's margin (#323 reports a
  local pass), and the release needs its run on the `v0.2*` tag. The 500-case
  gate's analytic SSI corpus holds no B-spline surfaces, and no corpus case

  `bench/`.

  fails at #322 with 30 defect records. See *Mandatory metamorphic release
  evidence*.

## Generic NURBS SSI supported domain for v0.2

This is the minimum **reference set** the release requires, not a declaration
of the full supported domain: six configurations of polynomial and
positive-weight rational B-spline surface pairs over finite parameter boxes,
from `corpus/nurbs-ssi/`, each at three placements (origin, tilted, far) and
two scales (x1, x100).

| Surface pair | Required configurations |
| --- | --- |
| Plane–plane | Transverse crossing and separation at ten pair tolerances |
| Saddle–plane | Two hyperbola branches and an interior transverse node in the reference placements |
| Bump–plane | A closed transverse loop at the documented depth of 0.001 at unit scale |
| Cylinder–plane | A circle and two generators from transverse intersection |
| Sphere–plane | A transverse circle, including the near-pole case |
| Cylinder–cylinder | Two transverse loops |

The 58 reference fixtures (29 configurations and placements, at both scales)
are generated by `tools/generate_nurbs_corpus.py`. Each carries a pair
tolerance of 1e-5 times its scale (0.00001 at x1, 0.001 at x100), so one
relative tolerance is tested. Each case must resolve in both operand orders
with its closed-form connectivity and point counts, certified branches, and
witness and pcurve checks. The remaining 32 fixtures are marked
`may_fail_closed`: specific tangencies, a near-coincident overlap, the
smallest loop, far placements of the saddle node, and a cylinder–cylinder node
on a knot and seam. All 90 are held to "no wrong answer" by "no nurbs-ssi
corpus case is answered wrongly, both ways" (`[.][exhaustive]`, run weekly
by `robustness.yml`, not on pull requests). That test accepts any fail-closed
refusal, not only a documented one. On pull requests, "no nurbs-ssi
configuration is answered wrongly" checks one operand order.

Run the strict check on a candidate through **Intersection release evidence**
using manual dispatch, or run it from a GCC 16 release build with
`./build/gcc16-release/tests/stereon_intersect_tests "[nurbs-ssi-release]"`.
The release check allows no solver refusals on reference fixtures. It runs
only on a `v0.2*` tag or a manual dispatch, not on pushes or pull requests
that change `src/`, and it requires at least 58 reference fixtures
(`REQUIRE(count >= 58)`) rather than a pinned list. The 500-case SSI
qualification, OCCT comparison and Tier C review remain open.
