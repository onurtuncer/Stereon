# Planar relation cells: MR-01 to MR-04 for every ordered pair of plane curves

- **Date:** 2026-11-12
- **Branch:** `verify/relations-planar`, stacked on the batch 2 triage (#272), with the planar corpus of #268 merged in
- **Policy:** [ADR-0053](../adr/0053-metamorphic-testing.md), [inventory](intersection-metamorphic.json)
- **Toolchain:** GCC 16.2 (MSYS2 UCRT64), preset `gcc16-debug`, Windows 11
- **Qualification correction (2026-11-12 audit):** all 144 cells are `MR implemented`, pending strict completeness evidence. The safety runs below accepted undocumented refusals and therefore do not qualify a relation under ADR-0053. Separate MR-04 completeness tests now expose those refusals with `[!mayfail]`; that tag never covers the geometric safety checks. Historical green counts below describe safety only.

- **Historical reviewer:** the v0.2 verification agent (Agent E). The earlier qualification is superseded by the correction above.

The 36 ordered pairs of `Line2d`, `Circle2d`, `Ellipse2d`, `Hyperbola2d`, `Parabola2d` and `BSplineCurve2d` each have four cells, 144 in all. Every cell is qualified by a test that runs the relation on that ordered pair against an independent oracle: the closed-form answers of [`corpus/planar-curves/`](../../corpus/planar-curves/README.md), generated by `tools/generate_planar_corpus.py` and never taken from the kernel. `BSplineCurve2d` covers both the polynomial (`spline`) and rational (`rational`) corpus kinds.

#### Domain

The domain is what the corpus covers, per its README. Each pair kind is tested in crossings, tangencies of order two and four, separations 3·2^-40 either side of a tangency, and coincident or overlapping arcs, at three placements and two scales. Those configurations are symmetric about a local axis, plus slanted lines.

- **Inputs:** every input is an exact double. The one exception is the rotated frame (3/5, 4/5) of an ellipse, hyperbola or parabola, so tangency and coincidence regimes with those conics are excluded at the rotated placement.
- **Refusals:** a refusal (`IntersectionFailed`, `NotImplemented`) is accepted as fail-closed and never counted as a pass of the relation. The corpus README and #268 list the refusals; they are completeness findings, not relation failures.
- **Out of scope:** user types, periodic B-splines and requested domains other than those in the corpus.

#### Relations as the tests run them

- **MR-01, rigid motion.** "no planar-curves corpus case is answered wrongly, both ways" (`tests/intersect/PlanarCorpusTests.cpp`, `[exhaustive]`) runs every configuration at `origin`, at `far` (a translation by (393216, -262144)) and at `rotated` (the rotation by atan(4/3), composed with a scale of 5 and a translation by (12, -7)). Each placement is checked against its own independently transformed closed form: positions, contacts, counts and overlaps. `rotated` composes a rotation with a uniform scale, so MR-01 and MR-03 are exercised together there; `far` is a pure translation.
- **MR-02, operand exchange.** The same test runs every case in both orders against the same expected set. Each point's parameter on each operand is checked by evaluating that operand.
- **MR-03, uniform scale.** The same test runs every configuration at scales 1 and 100. Both are exact here: the corpus asserts every input is a double. Planar intersection has no tolerance input, so no policy needs scaling. The scale is 100, not a power of two; exactness is asserted per input instead.
- **MR-04, equivalent reparameterization.** "MR-04: every planar-curves corpus case answers alike in an equivalent chart, both ways" is new in this branch. It moves each operand in turn to an equivalent chart, built exactly from the case data and not by the kernel:
  - a line's origin is moved two directions on and its direction doubled, so t = 2t' + 2;
  - a circle's frame is turned a quarter, t = t' + pi/2;
  - an ellipse's frame is turned half, t = t' + pi;
  - a hyperbola's or a parabola's y axis is negated, t = -t';
  - a B-spline is reversed (knots reflected, poles and weights reversed), t = a + b - t'.

  The result must still be the case's closed-form answer. Every reported parameter on the moved operand must map back, through that closed-form change of parameter, to the original curve at the reported point. Overlap ends map back the same way.

Coverage: every one of the 28 corpus families has at least one answered (not refused) case at every placement, at both scales and in both orders. The minimum, 1, is spline-rational at far x1. So each relation runs on real answers for each ordered pair, not only on refusals.

#### Replay

```sh
cmake --preset gcc16-debug
cmake --build --preset gcc16-debug --target stereon_intersect_tests
build/gcc16-debug/tests/stereon_intersect_tests "no planar-curves corpus case*"
build/gcc16-debug/tests/stereon_intersect_tests "MR-04: every planar*"
```

Every fixture is a committed corpus file; there is no random seed. The per-PR subsets are "no planar-curves configuration, rotated or else far, is answered wrongly" and "MR-04: each planar-curves configuration answers alike in an equivalent chart". The Robustness workflow's `[exhaustive]` job runs the full tests weekly.

#### Spot-checks: faults the cited tests kill

Each fault was applied alone to a working tree with no committed change to `src/`, rebuilt, and run twice; the source was then restored.

- **MR-02, line and circle:** `CircleLine2d` returns the line-first answer without exchanging the parameters (`SwappedPlanar` dropped). It is killed in both runs by the corpus test, and only in the line-circle family, the only one routed through that handler with the circle first.
- **MR-02, conic pairs:** `ConicConic2d` drops `SwappedPlanar` when it charts the second conic. It is killed in both runs in exactly the nine conic-conic families: circle with ellipse, hyperbola or parabola; ellipse with ellipse, hyperbola or parabola; hyperbola with hyperbola or parabola; and parabola with parabola.
- **MR-04, chart sense:** the B-spline handler's hyperbola parameter uses the x axis's perpendicular instead of the y axis. The corpus test does **not** kill it, because the corpus frames are right-handed. The new MR-04 test kills it in both runs, in hyperbola-spline and hyperbola-rational, where the reparameterization negates the y axis.
- **MR-01, translation:** the B-spline handler forms its pole offsets from the coordinate origin instead of the other curve's origin. It is killed in both runs at `circle-rational/along-far-x1` only. The same configuration passes at the origin and rotated placements, so the kill depends on the translation.

These are samples: they show that the cited tests detect relation-specific faults, not that every possible fault is detected.
